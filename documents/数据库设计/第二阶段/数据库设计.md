# 第二阶段数据库设计说明

[文档目录](../../README.md) · [第一阶段](../第一阶段/数据库设计.md) · [系统设计](../../系统说明/第二阶段/系统说明.md) · [关键逻辑](../../关键逻辑说明/第二阶段/关键逻辑说明.md)

本文按照业务顺序解释如何存储、为何设计及收益与代价。字段以当前[运行Schema](../../../code/数据库设计/第二阶段/运行规范/schemas.json)和实现为准：operation_keys是独立集合，contentHash是内容摘要，输入限制保存在content.validation中。

第一阶段八个集合保留：users/sessions负责账号会话，surveys/survey_versions负责草稿发布，attempts/responses负责填写答卷，participation_guards/submission_keys负责参与控制和提交重试。第二阶段新增八个业务集合、两个迁移集合，共18集合；只扩展两个旧validator，不删除历史或重建答案体系。

| 新增集合 | 随业务引入的用途 |
|---|---|
| question_resources、question_versions | 独立题目身份、工作稿、固定内容及来源。 |
| question_banks、question_bank_members | 分类组织，成员引用指定版本。 |
| question_grants | 作者向指定接收者开放明确版本的USE/FORK权。 |
| question_usages、usage_summary_grants | 反向定位实例，独立控制他人摘要可见范围。 |
| operation_keys | 新业务请求指纹与最小成功凭据。 |
| migration_runs、migration_items | 升级计划、检查点、来源哈希和防重。 |

下面继续以甲保存年龄题Q1、让A和B选用为例。

## 1. 题目的单独保存

原来题目只嵌在问卷内部，无法在尚无问卷时独立管理。新增question_resources保存身份，主要包括ownerId、createdBy、workingDraft、latestVersionId、revision、versionCounter及时间。未确定内容放workingDraft，固定后写question_versions，通过resourceId归属资源，保存versionNo、content、contentHash、来源及时间。

资源与版本拆开，是因为一道题与某次确定的内容不同。版本独立成文档，避免全部历史放进不断增长的资源数组；通常一起读取的题干、类型、选项和validation仍嵌入content，减少题目内部零碎关联。代价是历史需要查版本集合，并由后端保证归属及不可变性。

ADOPT在初版adoptionSource保存源surveyId、实例questionId、提取前definitionVersion/controlRevision、extractedAt、sourceQuestionSnapshot和sourceQuestionHash。引用说明从哪里来，提取快照说明当时是什么内容；只引用当前草稿无法抵抗后续修改和删除。这个快照只证明来源，不是填写使用的整卷快照，完整证据不随共享开放。

提取同时写资源、初版、出处、问卷改绑、使用行和成功凭据，必须同事务。独立operation_keys以`actorId + useCase + keyHash`唯一，保存requestFingerprint和最小结果；同键同指纹回放，异指纹拒绝。原submission_keys继续只管答卷，两个业务不混用回执。

## 2. 选入问卷的题目

甲让A、B选用Q1时，保留surveys.draft.questions执行字段，增加reuseBinding，包含resourceId、questionVersionId、contentHash、optionMap和semanticsSnapshot。两卷引用同一固定版，但分别保留questionId、必答、位置和跳转，原规则引擎继续执行。

这里有意保留执行副本：固定版说明内容依据，本卷实例说明如何使用。引用支持跨卷定位，嵌入避免原编辑填写每题都临时拼接资源。代价是写入和发布必须核对副本、绑定、哈希和语义一致，不能任意修改单份副本。

选择题optionMap保存`semanticOptionId ↔ localOptionId`，因为原跳转和答案仍用局部选项ID。换版须完整一一对应，不能用别卷编号或相同文字猜语义；数字、文本映射为空。

question_banks保存name、ownerId、state、revision及时间；question_bank_members保存bankId、resourceId、questionVersionId。`bankId + resourceId`唯一保证同库同题一个当前选版，同题可进多库。成员引用而不复制版本，更新分类或选版不改变A、B，题库软删除不级联删除资源和问卷。

## 3. 题目的修改和恢复

Q1更新时追加question_versions文档，resourceId说明归属，parentVersionId说明本资源父版，originKind区分创建、编辑、恢复、派生和ADOPT。固定内容不覆盖，题目更新不改实例或发布快照。

资源revision与versionCounter是第二阶段新增字段，沿用第一阶段并发控制思路：先CAS确认状态，再分配版本号，同事务写版本和凭据。`resourceId + versionNo`唯一防重复号，revision防陈旧覆盖，operation_keys防请求重放，三者不能替代。

恢复初版新增恢复版本，restoredFromVersionId记录依据，parentVersionId仍表达本链关系。A、B保持原选版，版本历史、题库选版和实例换版各自独立，既保留修改经过，又控制影响范围。

## 4. 共享题目

原surveys.ownerId只能表达问卷管理，不能表达甲允许乙使用哪个题目版本。新增question_grants保存resourceId、questionVersionId、grantorId、granteeId、actions、revision及时间，以`questionVersionId + granteeId`唯一。共享限定USE/FORK，不扩展为问卷管理或答案读取权。

乙修改共享题时，新建归乙的资源与初版，在derivedFrom保存甲的具体resourceId、questionVersionId。derivedFrom是跨资源来源，parentVersionId是本资源版本链，乙的后续版本不能写进甲历史。这样同时保护作者和保存来源，代价是不能仅凭同源推断所有权或统计可比性。

按接收者建立授权查询索引，版本的parentVersionId、derivedFrom、restoredFromVersionId建立来源索引，ADOPT还按源问卷、实例及编辑版本索引。题干、contentHash不作身份唯一键，相同文字或内容不等于同资源。

## 5. 查询题目和使用情况

若每次扫描全部草稿与历史题目数组，成本随发布次数增长。新增question_usages作反向投影，保存surveyId、surveyOwnerId、questionId、resourceId、questionVersionId、snapshotVersion、definitionVersion及时间。snapshotVersion=0表示草稿，正数表示发布版；`surveyId + snapshotVersion + questionId`唯一，资源/版本索引用于反查。

导入、换版、删除实例同步草稿行，发布增加发布行，旧发布关系保留。投影加快反查，也增加写入维护成本；它可重建，不是权限或历史权威。查询必须回到真实草稿或快照核对绑定，不能用过期投影冒充使用事实。

usage_summary_grants单独表达反方向授权：甲用question_grants让乙用题，乙授权甲看自己问卷的最小使用摘要。`surveyId + resourceId`限定范围并唯一，另存grantorId、recipientId、enabled、policyVersion、confirmedAt、revision及时间；接收者和资源索引用于过滤。

question_usages回答在哪里使用，usage_summary_grants回答向谁展示。首次确认与导入绑定同事务；关闭摘要同时推进问卷controlRevision，防旧页面重开。真实绑定和授权先于分组、计数和分页，最终只输出SUMMARY_V1九字段。摘要可关闭，引用和历史不删除。

## 6. 问卷的发布

survey_versions继续保存完整整卷定义，并固化绑定、选项映射和语义快照。后端依据固定版与实例检查是否固定、版本归属、内容一致及规则有效；Schema检查形状、BSON类型和本地约束，不能独自保证跨集合归属、哈希或不可变性。

| 内容 | 保存方式及权威范围 |
|---|---|
| 独立题目与固定版本 | 资源引用版本，content说明固定题意及输入限制。 |
| 本卷实例 | 嵌入执行内容并引用固定版，保存本卷必答和跳转。 |
| 整卷发布快照 | 固化完整定义及绑定，是旧attempt和答案解释依据。 |
| ADOPT提取快照 | 固化提取当时内容，仅证明来源。 |
| 使用投影 | 冗余定位字段，可由真实绑定重建。 |

固定版已有内容，发布仍再存一份，是为了保留整卷上下文并沿用原引擎。存储和一致性检查成本增加，但改版、恢复或题库删除不会影响旧填写。快照、发布使用行、发布指针和问卷CAS同事务，不能只有新指针而无快照。attempts和responses不增加题库来源字段，不改历史答案。

## 7. 跨问卷的题目作答统计

原responses按surveyId、publishedVersion找到快照，再按answers.questionId解释答案。本地questionId不能识别跨卷独立题，因此借原快照reuseBinding扩展成“资源/固定版→本卷实例→答案”，不新建答案集合，不自动纳入ADOPT前未绑定历史。

先核对所选surveys.ownerId，再限定多个surveyId，以`surveyId + participationId`分组按submissionSequence取最新成功整卷。之后关联原survey_versions与participation_guards，检查唯一关联、归卷、账号和整卷路径，再筛目标绑定、实例与非空答案。原响应排序索引、发布版本唯一索引和guard的_id索引继续使用，不据此声称大规模性能已验证。

独立账号数通过`responses.participationId → participation_guards._id → userId`内部去重。20和22各贡献一次，账号计一人，内部关联不公开。选择题借原optionMap还原语义，数字用Decimal求均值与分布，文本只给有效数量。

GROUPED保留版本和上下文；MERGED检查明确依据、同题型/测量/单位/时间/人群及完整选项对应。同源不直接证明可比，本版不转换单位。关联须检查基数，不能直接unwind丢行；完整读取并检查全部最新整卷后才返回，异常整份失败，不用少算结果冒充成功。

## 8. 旧数据的兼容与迁移

只扩展surveys、survey_versions的validator，接受原v1及可含完整reuseBinding的v2，其余六旧集合与索引保留。未绑定旧题仍能编辑、发布、填写和单卷统计；以后主动选用或ADOPT才建立可信绑定，不按题干补出处，不要求重建旧卷。

空专用库初始化目标，完整旧库先兼容运行。正式升级先停写，预检validator、索引、BSON类型、关联与哈希，备份BSON及DDL，先在新恢复副本审查，再新增集合/索引、扩展两个validator，验证后激活。本轮未迁移实际旧业务库，工具和隔离演练不能代替真实库审查。

DDL不能整体放一笔事务，migration_runs记录计划、规范、备份和检查点，migration_items记录来源集合、ID、阶段、哈希及创建结果。计划唯一、来源阶段组合唯一，配合业务唯一键和同一备份续跑，避免重复投影。默认不批量改旧问卷、快照、attempt或response，只对已有可信绑定补投影。

失败保留台账与数据。激活前、旧基线未变且无新业务/投影时，核对后恢复旧validator并清理本计划新增空结构；已激活或已有新数据则拒绝自动降级，保全现场，在不存在的新库恢复备份审查。responses旧v1、孤儿关联、未知结构或缺来源证据须另审，不能删历史换取成功。

索引和事务边界见[indexes.json](../../../code/数据库设计/第二阶段/运行规范/indexes.json)、[transaction_boundaries.json](../../../code/数据库设计/第二阶段/运行规范/transaction_boundaries.json)，具体操作见[运行升级说明](../../../code/README_PHASE2.md)。
