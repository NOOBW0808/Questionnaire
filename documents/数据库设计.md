# 在线问卷系统数据库设计文档

[文档目录](README.md) · [仓库首页](../README.md) · [运行代码](../code/README.md) · [测试材料](../test/README.md)


## 1 设计结论与依据

本方案使用8个 MongoDB 集合。问卷控制记录保存当前编辑定义和收集设置，已发布定义保存为独立版本快照；一次填写尝试与一份已提交答卷分别保存为独立文档。题目、选项、校验和跳转规则按问卷聚合嵌入，持续增长的答卷不嵌入问卷。支持发布后编辑题目和策略、随时修改截止时间、关闭后重新开放；旧尝试与旧答卷继续按绑定版本解释。允许重复时保留所有历史提交，但统计仅使用每账号最后一次成功提交的整份答卷。业务数据及会话均存于MongoDB。

本组合仓库提供设计说明、[权威 schemas.json](../code/数据库设计/schemas.json)、[可选索引和校验器安装脚本](../code/数据库设计/mongodb_schema.js)，以及 [Python 后端实现](../code/survey_app/)。业务提交由 filling.py 与 database.py 实现，统计由 statistics.py 实现；HTTP 接口见 [API说明](API说明.md)，测试证据见 [测试目录](../test/README.md)。

本文第 16 节保留数据库设计阶段参考包的文件清单，用于说明原方案背景。其中 model_examples.ejson、statistics_queries.js、submission_service.js、verify_database.js 和 validation_report.json 未包含在本组合仓库，也不是当前应用的运行依赖。下文涉及这些参考文件或数据库专项验证的陈述属于设计阶段记录，不等同于本次 API 测试或 Python 业务实现。

### 1 1 集合总览

| 集合 | 一个文档代表 | 增长方式 |
| --- | --- | --- |
| users | 一个注册账号 | 按账号增长 |
| sessions | 一个登录会话 | 过期后TTL清理 |
| surveys | 一个问卷及其当前编辑定义 | 每问卷一份 |
| survey\_versions | 一个不可覆盖的发布定义快照 | 按实际版本增长 |
| attempts | 一个账号的一次填写尝试 | 按填写次数增长 |
| responses | 一次历史成功提交，含账号内接纳序号 | 按成功提交增长 |
| participation\_guards | 账号问卷参与身份及接纳序号分配器 | 每问卷每账号一份 |
| submission\_keys | 一次成功提交的幂等凭据 | 每成功尝试一份 |

### 1 2 部署前提

目标为 MongoDB 7.0及以上的副本集部署。开发可使用单节点副本集，以支持多文档事务；独立 standalone 实例可以安装 schema，但不满足本方案的提交一致性要求。本次真实验证环境为 MongoDB 8.3.11 单节点隔离副本集，未据此宣称其他版本或生产负载已通过验证。

## 2 聚合边界与集合关系

问卷定义通常整体编辑、整体发布和整体读取，题目又依赖本问卷的顺序、选项与跳转目标，因此嵌入同一份定义。用户、会话、版本、填写和提交的生命周期、增长速度与授权范围不同，使用引用关联，避免一个文档无界增长。


### 2 1 为什么不照搬关系表结构

将题目、选项、每条校验、每条跳转分别建成表状集合，会把一次读取问卷拆为多次查询或多重 $lookup，也削弱定义整体修改与发布的原子边界。这里按业务聚合嵌入这些有界对象；版本和答卷等独立生命周期对象仍分开引用。关系数据库也能实现本业务，本方案的选择依据是课程约束和实际访问方式，不声称关系模型无法完成。

### 2 2 冗余范围

已发布快照重复定义，是为保留历史语义；attempts 与 responses 分别保留保存态和提交态，是为分离编辑生命周期；答卷中的 type、anonymous 和 visitedQuestionIds 是经服务端验证的快照。用户名、密码、题目标题和全部选项不在每份答卷复制，统计也不另维护一套容易漂移的选项计数。

## 3 标识 类型与版本约定

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id 与跨集合引用 | ObjectId | 账号、问卷、尝试、答卷等主键与引用保持同一类型；API用24位十六进制字符串映射。 |
| questionId optionId ruleId | String | 服务端生成稳定且不复用的局部标识；目标引用标识，不使用可变题号。 |
| publishedVersion | Int32 | 问卷内从1递增的发布版本号；不等同于定义编辑次数。 |
| definitionVersion | Int32 | 每次编辑递增；包括即时截止时间修改。版本快照记录sourceDefinitionVersion。 |
| controlRevision | Int64 | 发布、关闭、截止或策略变化的控制版本；用于管理ETag与条件更新。 |
| revision writeFence acceptedCount | Int64 | 分别为尝试版本、问卷写入栅栏、账号累计接纳次数；使用Long而非JS浮点计数。 |
| 时间字段 | Date | BSON UTC毫秒时间；不存本地日期文本。deadlineAt=null表示无截止。 |
| 数字答案及数字阈值 | Decimal128 | API十进制字符串严格转换；拒绝NaN、无穷和无法精确表达的输入，不静默舍入。 |
| schemaVersion | Int32 | responses取2，其他集合取1；物理结构版本独立于业务发布版本。 |

### 3 1 乐观并发版本

管理 ETag 可编码 definitionVersion 与 controlRevision，例如 definition-7-control-3；客户端将其视为不透明值。所有管理写操作匹配创建者和控制版本，编辑还匹配定义版本。仅提交、开始、保存所增加的 writeFence 不改变管理 ETag，避免填写流量使编辑请求无故冲突。尝试 ETag 独立采用 revision。

### 3 2 技术容量边界

schema 暂设每定义最多200题，每题最多100个选项和100条跳转，每个文本答案最多10000个码点。这是为文档大小与请求资源设置的工程上限，不是原文要求；可评审后调整。应用在写入前测量完整 BSON，建议不超过8 MiB，保留低于 MongoDB 16 MiB 文档上限的空间。数组数量限制不能单独保证总字节数。

Decimal128 有34位有效数字及有限指数范围，超出可精确表达范围应提示输入范围错误。统计用十进制运算；接口均值按架构约定返回最多4位小数的字符串或null。

## 4 账号与会话模型

### 4 1 users

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id | ObjectId | 账号主键。 |
| schemaVersion | Int32 | 当前为1。 |
| username | String | 展示名称，1至64个码点。 |
| usernameKey | String | 按统一Unicode规范化及大小写折叠生成，唯一索引控制注册冲突。 |
| passwordHash | String | 带算法参数和盐的Argon2id等密码哈希；不保存password明文字段。 |
| createdAt | Date | 注册时间，由服务器生成。 |

规范化算法应在注册、登录和改名中保持一致，并在上线前固定版本；例如NFKC后casefold。数据库只能确保 usernameKey 唯一，不能自行验证它确实由 username 按约定计算，也不能凭字符串长度判断密码哈希是真实可用的安全哈希。

### 4 2 sessions

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id userId | ObjectId | 会话主键及所属账号引用。 |
| schemaVersion | Int32 | 当前为1。 |
| tokenHash | String | 随机高熵会话令牌的SHA-256摘要，64位十六进制；Cookie仅携带原令牌。 |
| csrfToken | String | 独立随机CSRF令牌，供已认证的/auth/me返回，不是会话凭证。 |
| createdAt expiresAt | Date | 创建和到期时间；expiresAt设置TTL单字段索引。 |

### 4 3 过期与退出

TTL 删除异步执行，不能把“记录尚存在”等同于“会话有效”。每次认证还须比较 expiresAt 与服务器当前时间；退出时删除当前会话。users 与 sessions 不向问卷创建者开放直接查询，所有接口都屏蔽 passwordHash 与 tokenHash。

```javascript
users:    { _id, schemaVersion, username, usernameKey,
            passwordHash, createdAt }
sessions: { _id, schemaVersion, userId, tokenHash,
            csrfToken, createdAt, expiresAt }
```

## 5 问卷控制与编辑定义模型

### 5 1 surveys

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id ownerId | ObjectId | 问卷主键及创建者；管理操作条件必须同时限定这两个值。 |
| publicCode | String | 16至64位随机URL安全标识，全局唯一；不随修改或重新开放变化。 |
| state | String | 只存DRAFT、PUBLISHED、CLOSED；EXPIRED由状态和deadlineAt派生。 |
| definitionVersion | Int32 | 编辑版本；从1起，条件更新后递增。 |
| controlRevision | Int64 | 所有管理控制变更递增，用于避免覆盖和状态冲突。 |
| publishedVersion | Int32或null | 当前生效快照的版本号；DRAFT必须为null，其他状态必须为正整数。 |
| deadlineAt | Date或null | 即时生效的收集截止时间，独立于题目快照。 |
| draft | Object | 完整可编辑定义，内部嵌入题目、选项、校验与跳转。 |
| writeFence lastGateAt | Int64 Date或null | 开始、保存和提交通过真实写入栅栏排序；lastGateAt由数据库写入时间生成。 |
| createdAt updatedAt | Date | 创建及管理编辑时间；填写增加writeFence不更新updatedAt。 |

### 5 2 定义结构

```javascript
draft: {
  title: "课程活动调查", description: "示例问卷",
  policy: { anonymous: true, allowRepeat: false },
  questions: [ /* 有序题目数组 */ ]
}
```

questions 数组的位置即题目顺序，不另存容易矛盾的 order 数组或序号。draft 可暂时没有题目；发布快照要求至少一题，选择题至少两个选项。完整发布检查还必须验证题目与选项标识唯一、引用有效、规则优先级和向后跳转。

草稿、已发布、已关闭与已截止时均允许编辑。编辑题目与策略后，调用发布流程切换生效快照；未发布的修改不会影响正在填写的旧版本。截止修改即时作用于所有尝试，手动关闭仍需显式重新开放。

## 6 发布版本与题目模型

### 6 1 survey\_versions

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id surveyId | ObjectId | 快照主键与所属问卷引用。 |
| publishedVersion | Int32 | 问卷内唯一递增编号，与surveyId组成唯一索引。 |
| sourceDefinitionVersion | Int32 | 发布时读取的编辑版本，便于追踪来源与识别未变更发布。 |
| definition | Object | 完整有效定义，包含title、description、policy与questions。 |
| publishedAt | Date | 该定义首次生效的时间。 |

发布事务插入快照并更新 surveys.publishedVersion。关闭后若定义未改变，可复用原版本重新开放；定义已改变则生成新版本。旧快照不被普通业务更新和删除，旧答卷引用始终有效；schema校验器本身不能阻止“结构合法的覆盖”，还需仓储接口和集合权限约束。

### 6 2 嵌入题目的共同字段

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| questionId | String | 本定义内唯一且跨版本保持稳定的题目标识。删除后不复用。 |
| type | String | SINGLE、MULTIPLE、TEXT、NUMBER四个接口类型；后两者属于填空题。 |
| title required | String Bool | 题干和是否必答。 |
| options | Array of Object | 仅单选与多选有此字段，每项为optionId及label；顺序就是显示顺序。 |
| validation | Object | 按题型保存相应配置，禁止混入无关题型参数。 |
| jumpRules | Array of Object | 按规则优先级执行；文本题固定为空数组。 |

### 6 3 版本快照不等于禁止修改

不变的是历史快照，创建者仍可编辑当前定义、调整策略和截止时间并重新开放。新尝试读取当前生效定义；旧尝试保持绑定版本。策略中匿名承诺在开始时快照，重复限制按当前生效版本读取，截止则始终使用当前控制记录。

## 7 校验规则与跳转结构

| 题型 | validation中的字段 | 存储方式 |
| --- | --- | --- |
| SINGLE | 空对象 | 无多选数量或数值校验字段 |
| MULTIPLE | minSelections maxSelections exactSelections | 可选Int32非负数；跨字段一致性由发布服务检查 |
| TEXT | minLength maxLength | 可选Int32非负数；对规范化文本按码点计数 |
| NUMBER | minValue maxValue integerOnly | 边界为Decimal128；integerOnly为必有Bool |

空答案规则遵循系统架构：可选题显式空值可继续；被合法跳过的题不做必答校验。必答多选至少一项；精确数量、上下限、选项总数须一致。题型schema负责字段形状，题目实际约束值由服务端在发布和提交时解释。

### 7 1 跳转规则

```javascript
{ ruleId: "r1", priority: NumberInt(10),
  operator: "EQ", value: "no", target: "END" }

{ ruleId: "r2", priority: NumberInt(20),
  operator: "BETWEEN",
  value: [NumberDecimal("18"), NumberDecimal("60")],
  target: "q5" }
```

| 来源题型 | operator | value类型 |
| --- | --- | --- |
| SINGLE | EQ | 一个optionId字符串 |
| MULTIPLE | ANY\_OF ALL\_OF EXACT\_SET | 不重复的optionId字符串数组 |
| NUMBER | EQ GT GTE LT LTE | 一个Decimal128 |
| NUMBER | BETWEEN | 恰好两个Decimal128，含边界 |
| TEXT | 无 | 不配置条件跳转 |

规则嵌入所属题目，因此不重复保存 sourceQuestionId。target 为目标题标识或保留字END；生成题目标识不得使用END。priority在本题内唯一，第一条匹配规则生效，未命中时进入数组下一题。配置是数据，执行器只实现操作符语义，不写死具体问卷编号或路径。

### 7 2 发布服务补充检查

检查所有ID唯一、规则目标属于本定义、目标在当前题之后、条件引用选项存在、BETWEEN下界不高于上界、数字有限且可精确存储。uniqueItems只保证整个数组项不完全相同，不能替代“不同对象中的questionId不能相同”的检查。

## 8 填写尝试模型

### 8 1 attempts

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id surveyId userId | ObjectId | 尝试主键、问卷、填写账号；必须按\_id与userId授权读取和保存。 |
| publishedVersion anonymous | Int32 Bool | 开始时绑定的发布版本与匿名承诺；修改问卷不能追溯改变。 |
| revision | Int64 | 已保存答案的乐观并发版本。 |
| state | String | IN\_PROGRESS或SUBMITTED。 |
| answers | Array of Object | 每题一项，包含questionId、type、value；保存完整替换，非原地无限追加。 |
| visitedQuestionIds | Array of String | 服务端从绑定定义计算的实际经过路径，不信任客户端路径。 |
| nextQuestionId | String或null | 下一待答题；到END为null。 |
| responseId submittedAt | ObjectId或null Date或null | 未提交时均为null；提交后均有值，并与对应答卷一致。 |
| createdAt updatedAt | Date | 开始与最近保存或提交时间。 |

### 8 2 答案联合类型

```javascript
[
  { questionId: "q1", type: "SINGLE", value: "yes" },
  { questionId: "q2", type: "NUMBER", value: NumberDecimal("20") },
  { questionId: "q3", type: "MULTIPLE", value: ["apple"] },
  { questionId: "q4", type: "TEXT", value: "" }
]
```

SINGLE和NUMBER可选空值为null；MULTIPLE为空数组；TEXT为空字符串。答案项缺失表示尚未填写，不与显式跳过混淆。题型冗余使聚合可直接判断值类型，但必须与绑定版本中的题型一致。

### 8 3 保存与失效答案

保存匹配尝试归属及revision，按绑定版本校验非空答案并重算路径，去除跳转后失效答案，再递增revision。尝试允许部分答案；不能仅凭schema中nextQuestionId=null就认定完成。旧尝试读取原题目定义，当前关闭、截止和重复策略仍在开始或提交等用例中检查。

不为attempts配置TTL；“每次填写保存”不应因未经评审的自动清理丢失。归档或保留期限属于后续明确需求。

## 9 已提交答卷模型与匿名

### 9 1 responses

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id surveyId attemptId | ObjectId | 历史答卷主键及问卷、尝试引用；attemptId唯一。 |
| participationId | ObjectId | 由参与记录\_id生成；同账号同问卷跨版本稳定，不接受客户端指定。 |
| submissionSequence | Int64 | 事务中从acceptedCount分配；同参与身份递增，最大者是最新有效答卷。 |
| publishedVersion | Int32 | 解释答案和分组统计的历史版本，不强制等于当前生效版本。 |
| anonymous | Bool | 从尝试复制的匿名承诺。 |
| respondentUserId | ObjectId 可省略 | anonymous=true时禁止存在；false时必须存在。 |
| answers | Array of Object | 最终合法路径上的规范化答案；类型与attempts相同。 |
| visitedQuestionIds | Array of String | 已完成实际路径，包括显式跳过的可选题，用于reachedCount。 |
| acceptedAt | Date | 事务中通过控制栅栏的数据库时间，映射接口submittedAt。 |
| schemaVersion | Int32 | responses结构版本2，新增参与身份与接纳序号。 |

responses只包含成功接纳的答卷，因此不再设置可变DRAFT或FAILED状态；统计先按participationId选择submissionSequence最大的整份答卷。一次尝试只产生一份；插入答卷、更新尝试、分配序号与幂等凭据在同一事务完成。不可变性还依赖业务写入口和权限，validator只校验结构。

### 9 2 对创建者匿名的边界

匿名答卷不保存respondentUserId，但内部participationId可通过参与记录关联账号，以支持跨版本去重和重试。此设计兑现“对创建者匿名”，不声称对数据库管理员或系统运营者不可关联。问卷创建者不拥有MongoDB账号和这些内部集合的直读权限。

统计和填空列表使用白名单投影，仅返回统计值、版本、题目标识与填写内容；不返回responseId、attemptId、participationId、submissionSequence、userId或可反查的内部标记。分页游标如包含内部主键，应使用认证加密形成不透明令牌。答案内容本身由填写者输入，系统不能消除其主动填写身份信息的可能。

### 9 3 发布后匿名策略变化

匿名变为非匿名仅影响此后新建尝试；已开始与已提交匿名记录仍不显示身份。统计必须逐记录应用其匿名承诺，不能根据surveys当前策略决定历史记录是否暴露身份。

## 10 参与身份 提交序号与幂等

### 10 1 participation\_guards

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id surveyId userId | ObjectId | 主键和问卷账号组合；组合唯一，不因发布新版本而新建。 |
| acceptedCount | Int64 | 累计历史成功提交次数及序号源；从0增长，不是统计人数。 |
| updatedAt schemaVersion | Date Int32 | 最近成功接纳时间及结构版本。 |

allowRepeat=false要求acceptedCount=0才可接纳；true可继续递增。事务用findOneAndUpdate返回递增后值，写入responses.submissionSequence。同一参与身份只选最大序号统计；并发提交按成功事务顺序形成序号，不按客户端时间或HTTP响应先后。策略改为禁止重复后保留历史及最后有效结果。

### 10 2 submission\_keys

| 字段 | BSON类型 | 含义与约束 |
| --- | --- | --- |
| \_id userId | ObjectId | 凭据主键及幂等键所属账号。 |
| keyHash | String | 客户端Idempotency-Key的SHA-256摘要；与userId组成唯一索引。 |
| requestFingerprint | String | 对userId、attemptId及提交If-Match作规范化编码后摘要，绑定同一次请求。 |
| attemptId responseId | ObjectId | 已提交尝试及返回的既有答卷标识；attemptId单独唯一。 |
| submittedIfMatch | String | 成功提交时请求携带的尝试ETag，供重放一致性比对。 |
| createdAt schemaVersion | Date Int32 | 凭据产生时间及结构版本。 |

提交体为空，最终答案来自最后一次保存；指纹不重新读取已改变的尝试revision计算。重放先查凭据并验证账号、尝试和指纹，再返回既有responseId，即使此后关闭或截止；不同尝试复用同一账号的键返回409。相同尝试换新键也不生成第二份答卷。

### 10 3 历史保留与统计去重

参与记录的surveyId与userId唯一，确保一个稳定参与身份。responses的participationId与submissionSequence唯一，允许历史多份但防止同序号重复。无需在答卷保存可变isLatest标记，也不覆盖旧答卷；统计按最大序号选择整份。网络重放只返回旧结果，不递增序号，更不会把旧答卷重新变成最新。

本阶段不对参与计数或幂等凭据设置TTL。它们的保留期必须覆盖需要重放和去重的历史；否则可能让已完成请求被当成新请求。

### 11 1 使用边界

## 12 发布 编辑与保存的一致性

### 12 1 编辑与发布

编辑使用\_id、ownerId、definitionVersion和controlRevision条件更新surveys.draft，并递增相应版本；匹配失败返回409。发布先检查完整定义，再在事务内重新匹配来源版本，插入新survey\_versions并切换publishedVersion、state、控制版本与更新时间。唯一版本索引避免并发产生同号快照。

若定义未改变，publish可返回已有生效版本；从CLOSED重新开放也可复用旧快照。若修改已保存但未发布，管理端同时展示编辑定义与生效版本，填写端始终获取生效快照，不读取draft。

### 12 2 开始与保存

开始、保存和最终提交都检查当前收集状态与deadlineAt。为与关闭、截止修改形成数据库写冲突，在事务中对同一surveys文档执行真实$inc writeFence，并由$currentDate写lastGateAt。只读状态或把同一个值重新$set回去，不能可靠形成所需冲突。

开始事务读取当前生效版本并插入attempts，快照匿名设置；禁止重复时可提前检查参与计数改善体验，但最终提交仍需重新判断。保存事务匹配userId和revision，按绑定版本重算并更新答案，与控制栅栏写入一起提交。

### 12 3 即时截止与策略切换

截止修改直接更新surveys.deadlineAt和管理版本，可在已发布、关闭或已截止状态进行；不修改题目快照。截止延后或置null只会让PUBLISHED状态恢复可填，不会让CLOSED自动开放。匿名与重复策略随新定义发布生效；新开始使用当前匿名策略，所有最终提交读取当前重复策略。

### 12 4 写入栅栏的代价

同一问卷的开始、保存和提交都会写控制文档，形成热点并增加事务冲突。这是课程规模下优先选择可说明的一致性边界，不是面向极高并发的最优结构。后续若分散计数或采用租约、分区栅栏，需要重新证明关闭与截止的接纳顺序，不能直接删去共享写操作。

```javascript
// 管理控制更新和接纳操作都必须实际写同一surveys文档
{ $inc: { writeFence: NumberLong(1) },
  $currentDate: { lastGateAt: true } }
// 业务提交使用readConcern snapshot及writeConcern majority
```

## 13 最终提交的事务边界

使用副本集多文档事务，readConcern为snapshot，writeConcern为majority。以下步骤全部在同一事务中执行；业务答案由后端按绑定版本重算并校验，不是由验证脚本替代最终应用实现。

1. 按userId与keyHash查询submission\_keys。存在时验证指纹；一致则返回原结果，冲突则返回409。此分支早于当前关闭和截止检查。

2. 读取并验证attempts的归属、IN\_PROGRESS状态和提交If-Match。读取绑定survey\_versions，确认全部答案和实际路径有效。

3. 条件更新surveys：state为PUBLISHED且未截止；递增writeFence并记录lastGateAt。读取当前生效版本的allowRepeat，关闭和策略变化通过共享实际写入确定先后。

4. 按surveyId与userId取得或建立唯一参与记录；禁止重复且已有成功提交则拒绝。findOneAndUpdate递增acceptedCount并返回新值，作为本次submissionSequence；其\_id作为participationId。

5. 插入responses，保存participationId与submissionSequence、绑定版本、匿名承诺及完整答案路径；acceptedAt取栅栏时间。匿名不写respondentUserId。最大序号自然替换统计依据，不改历史答卷。

6. 条件更新attempts为SUBMITTED并写responseId、submittedAt，递增revision；插入submission\_keys。提交事务后才向客户端返回成功。

### 13 1 时间与竞争顺序

接纳时间定义为成功事务中控制栅栏命令通过条件检查的数据库时间，acceptedAt保存该值；它不是HTTP到达时间或物理commit完成的墙钟时间。截止在此时已到则拒绝；栅栏通过后事务可能稍晚提交。若验收要求“commit必须发生在截止前”，需要另行收紧时间语义，当前方案不作此保证。

关闭或截止修改与提交写同一surveys文档，先提交的写入迫使竞争事务重试并重读控制值。失败事务不留下计数、答卷、尝试状态或幂等凭据的一部分。保存后关闭再重新开放，可继续原尝试，当前规则仍会重新检查。

### 13 2 重试与异常映射

TransientTransactionError重试整个事务；UnknownTransactionCommitResult优先重试同一次commit，不能直接假定失败再生成新答卷。唯一键冲突后在新事务或新快照下查幂等凭据或参与记录，区分重放、禁止重复与版本竞争。验证脚本给出有限重试示例，业务系统还须设置时间预算。

MongoDB错误121映射配置或值类型校验失败；11000按具体索引映射用户名冲突或提交竞争，不能统一解释为“用户名重复”。

## 14 统计数据模型与聚合

仅用responses中的每账号最新成功答卷统计。先按surveyId匹配，按participationId及submissionSequence倒序取每人第一份整卷，再按publishedVersion筛选和分组。不能先过滤版本、题目或非空值，否则旧答案会回流。历史答卷继续保留，但不重复贡献人数。

| 结果 | 计算方式 | 边界 |
| --- | --- | --- |
| submittedCount | 每参与身份选最新整卷后计数，按版本及总数分别统计 | 表示提交人数；同账号提交三次仍为一人 |
| reachedCount | 展开最新整卷的visitedQuestionIds后分组 | 最新答卷跳过题不计，不使用历史路径 |
| answeredCount | 展开最新整卷answers后排除空值 | 每人最多一次；最新留空不回填旧答案 |
| 选项人数 | 只展开最新整卷的单选或多选数组后分组 | 同账号每选项最多一次，旧选项被替换 |
| 数字平均值 | 只对Decimal128非空数字执行$avg | 空分组显示null，不以0代替 |
| 文本与数字内容 | 先选最新整卷，再按版本题目过滤分页 | 历史内容不列出；匿名身份不暴露 |

### 14 1 一个读取时点

同一次统计使用snapshot事务；先选择每账号最新整卷，再用$facet生成人数、版本、路径、回答及选项数，读取版本定义补零。facet输出及BSON结果也有大小限制，版本很多时应分页或分批处理，不把所有答卷内容汇总成一个巨大数组。

定义用于列出未被选择的选项；例如某人从A改选B，A须补为0，B计1。只做$group不能产生零值。数字均值用Decimal128计算，统一在输出时按架构约定四舍五入为最多4位小数；不使用$round的默认偶数舍入代替该语义。

### 14 2 不同版本的例子

甲在版本1先后填10、20、30，仅30有效；乙填50，均值为40、人数为2。甲再在版本2填100，甲旧版本统计贡献移除：版本1只剩乙50，版本2为甲100，总人数仍2。按版本1筛选也不能恢复甲的旧答案。

### 14 3 聚合与分页的负载

在线聚合从历史事实中选择最新有效结果，不维护容易漂移的选项计数缓存。数据量增长后可增加可重建的统计读模型，但必须带版本与处理进度，不能把异步缓存标作当前精确结果。答案分页使用版本、acceptedAt、\_id稳定排序；游标不要求跨页快照，API按架构说明此边界。

## 15 MongoDB schema与业务校验边界

schemas.json是完整可执行校验器的权威文件，涵盖8集合，包含BSON类型、required、additionalProperties、oneOf题型分支、数组上限和匿名条件。所有集合使用validationLevel=strict与validationAction=error；禁止业务账号绕过文档验证。

```javascript
// responses中匿名条件的结构摘录
oneOf: [
  { properties: { anonymous: { enum: [true] } },
    not: { required: ["respondentUserId"] } },
  { properties: { anonymous: { enum: [false] } },
    required: ["respondentUserId"] }
]
// 必须结合完整root required与additionalProperties使用
```

| 由哪一层保障 | 能够保障 | 不能据此推断 |
| --- | --- | --- |
| $jsonSchema | 值类型、必有字段、题型字段集合、可选空值、状态所需结果字段、匿名身份字段条件 | 不会自动检查引用存在、答案符合某题配置或快照不可改 |
| 唯一与TTL索引 | 账号规范键、分发码、问卷版本、尝试结果、幂等键、参与记录唯一；会话到期清理 | TTL不保证到时立即删；多键唯一不限制同文档ID重复 |
| 后端领域规则 | 有限Decimal128、题目ID唯一、上下限、选项引用、跳转、必答、路径和所有权 | 不能用前端校验替代；不能假定客户端提供的type和路径可信 |
| 事务与条件更新 | 接纳与控制变更排序、序号和答卷一起生效、版本CAS、幂等重放 | snapshot只读不会自动锁住其他文档；必须存在共享实际写入 |

### 15 1 数据更新权限

业务账号对survey\_versions和responses只授予必要的find与insert，普通业务不授予update或remove；attempts与控制记录按流程更新。部署账号负责createCollection、createIndex和迁移；MongoDB集合级权限不提供“当前用户只能看自己”的行级语义，所有权仍由后端条件执行。

### 15 2 演进与迁移

schemaVersion只区分物理结构。新增题型需更新oneOf、后端规则和统计策略；迁移先允许新旧结构读取，再回填验证，最后收紧schema。已发布业务版本与旧答卷不得因一次collMod失去解释依据；初始化脚本不会自动覆盖已有集合的验证器。

## 17 最新有效答卷与历史迁移

### 17 1 统计流水线

```javascript
// 先授权surveyId，再选择每个参与身份的最大接纳序号
{ $match: { surveyId } },
{ $sort: { participationId: 1, submissionSequence: -1 } },
{ $group: { _id: "$participationId", latest: { $first: "$$ROOT" } } },
{ $replaceRoot: { newRoot: "$latest" } }
// 此后才筛选publishedVersion或questionId、排除空值并聚合
```

这一顺序同时适用于问卷概览、单题统计、文本和数字列表、均值与分页。不能只修submittedCount而保留旧选项次数或旧文本；不能按题取最后一条非空答案，也不能先取分页再去重。

### 17 2 最后一次的确定规则

最后一次是最后成功接纳，不是最后开始或最后保存。事务写入surveys栅栏和参与计数，将同账号提交排成递增序号；即使acceptedAt毫秒值相同也由序号确定唯一最新。事务失败、校验失败和未提交草稿均不分配持久序号。重放旧幂等键返回旧结果，不改变最新有效答卷。

选择的是整份答卷：新路径跳过旧题，旧题的人数与内容随之移除；可选留空也替换旧值。跨版本先选最新，旧版本筛选不复活历史答案。每份答卷的匿名承诺保持不变，统计对最新有效答卷按其承诺投影。

### 17 3 已有数据的迁移顺序

本次只在隔离新库验证，没有改动用户已有数据库。若已有1.0结构数据，先备份并停写提交及统计入口，再用attemptId关联attempts.userId，按surveyId与userId定位或补建参与记录，将其\_id回填为participationId。引用缺失或归属矛盾先隔离核查，不猜测账号。

每账号每问卷按旧acceptedAt和\_id稳定排序，回填从1递增的Long序号、responses.schemaVersion=2，并核对acceptedCount及幂等引用。旧记录同毫秒时无法从现有字段恢复真实先后，须明确采用\_id顺序作为历史迁移约定；新提交不再依赖该约定。原始历史记录和旧字段应先另存备份。

核对每条答卷的参与身份与尝试归属、序号唯一、最大序号结果及匿名输出后，再创建新索引并收紧validator，最后切换统计与提交代码并恢复流量。禁止新旧统计混用或在回填前按缺失participationId分组；初始化脚本仍只用于新库，不自动迁移或清库。

### 17 4 验收例子

甲先选A、后选B、再选B：历史3份，人数1，A=0、B=1；乙也选A后人数2、A=1、B=1。甲第四次只保存草稿或提交失败，结果不变；甲下一次成功留空或跳过某题，旧答案不再参与该题统计。完整真实检查项见validation\_report.json。
