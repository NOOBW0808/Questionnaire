# 在线问卷系统说明

[文档目录](README.md) · [仓库首页](../README.md) · [运行代码](../code/README.md) · [测试材料](../test/README.md)

## 1. 系统用途

本系统是一个简化的在线问卷平台，支持注册用户创建问卷、配置题目与跳转规则、发布并通过 URL 分享问卷。填写者登录后作答、保存和提交，创建者查看选择题人数统计、文本答案和数字答案平均值。

系统支持单选、多选、文本填空和数字填空四种题型，并提供必答、数量、长度、数值范围及整数限制。问卷可以设置匿名填写、是否允许重复填写和截止时间。

## 2. 用户与权限

| 使用身份 | 主要能力 |
|---|---|
| 未登录访客 | 注册、登录；不能通过 API 获取问卷内容或提交答案。 |
| 问卷创建者 | 管理本人问卷，维护题目与策略，发布、关闭并查看统计。 |
| 已登录填写者 | 通过分享链接填写问卷，保存草稿，提交并查看本人的填写记录。 |

创建者与填写者属于同一种注册账号，无须单独分配角色。匿名表示对问卷创建者隐藏填写者身份，仍须登录；系统内部保留必要关联，用于权限控制和重复填写判断。

下表中的 `static/` 和 `survey_app/` 均相对于 [code](../code/README.md) 目录。

## 3. 系统结构

系统采用模块化单体架构：浏览器访问同一个 Python 后端，后端完成业务处理并读写 MongoDB，减少课程项目中的部署与协作成本。

```text
浏览器：登录、问卷工作台、编辑、填写、统计页面
                         ↓ 同源 HTTP / JSON
Flask 后端：账号会话 → 问卷管理 / 填写提交 / 统计查询
                         ↓ 共用规则与数据库事务
MongoDB 副本集：账号、会话、问卷、版本、填写与历史答卷
```

架构设计将职责划分为展示层、接口层、应用层、领域层和基础设施层。代码按这些职责组织，但接口处理与应用编排集中于业务模块，未单独建立完整的领域对象层和仓储接口层。

| 模块 | 实现位置 | 职责 |
|---|---|---|
| 页面交互 | `static/` | 提供问卷操作页面，通过 API 与后端交互。 |
| 账号与会话 | `survey_app/security.py` | 注册、登录、身份认证、CSRF 校验和分页游标。 |
| 问卷管理 | `survey_app/management.py` | 编辑、题目排序、规则配置、发布、关闭与所有权检查。 |
| 规则计算 | `survey_app/domain.py` | 发布检查、题型校验、精确数字处理和填写路径重算。 |
| 填写与提交 | `survey_app/filling.py` | 开始填写、保存答案、提交、重复限制与幂等处理。 |
| 结果统计 | `survey_app/statistics.py` | 按账号最新答卷统计，提供单题统计和答案分页。 |
| 数据与通用支持 | `survey_app/database.py`、`common.py`、`__init__.py` | 初始化 schema 与索引，组织事务，统一响应、错误和请求标识。 |

## 4. 主要使用流程

1. 用户注册并登录，创建问卷草稿。
2. 设置问卷标题、策略、截止时间，添加题目、校验和跳转规则。
3. 发布时后端检查定义并生成发布快照，用户分发分享链接。
4. 填写者登录后开始填写，本次填写绑定开始时的发布版本；保存答案时由后端计算有效路径。
5. 提交时检查收集状态、截止时间、重复策略和答案完整性，成功后保存历史答卷。
6. 创建者查看统计；同一账号对同一问卷只贡献最后一次成功提交的整份答卷。

## 5. 关键业务约定

### 5.1 发布与版本

问卷发布后仍可编辑，关闭后可以重新开放。题目和策略修改在再次发布后用于新填写，已有填写继续按原绑定版本处理；当前收集状态和截止时间则始终约束后续开始、保存与提交。

发布前会检查题目、选项、校验条件与跳转规则是否完整、可执行。发布快照用于解释对应版本的答案，后续编辑不会直接改写历史定义，避免新旧填写混用规则。

### 5.2 校验与跳转

后端先校验答案，再按优先级从小到大匹配规则，采用首条命中的跳转；未命中则进入下一题。目标仅限后续题目或结束，合法跳过的必答题不阻止提交。修改前面的答案后，系统重新计算路径并清除失效答案，确保正式答卷与实际填写路径一致。

校验包括选项有效性、选择数量、文本长度及数字范围等。例如“校园活动调查”中选择“不参加”可直接结束，后续必答题随路径一同跳过。填写路径由服务器计算，不能由前端自行指定。

### 5.3 填写与保存

每次开始填写生成独立记录，绑定账号和发布版本。保存允许问卷未完成，但已处理的答案须符合校验要求。系统通过归属检查和修订号防止越权及同一记录被旧页面覆盖，保存成功后才能确认进度已持久化。草稿和失败提交不参与统计。

修订号只比较同一份填写记录：一个页面保存后，另一页面使用旧修订号保存会被拒绝，不同用户的独立记录不受影响。已保存进度可以在刷新或重新登录后恢复；可选题需要明确保存空值，才能与尚未处理的题目区分。

### 5.4 提交与重试

最终提交重新检查权限、版本、收集状态、截止时间、重复策略及路径完整性，并通过事务统一保存答卷、分配提交序号和更新填写状态。幂等机制使同一成功请求的重试返回原结果，避免重复生成答卷；即使问卷随后停止收集，原成功请求仍可重放。每份填写最多提交成功一次，允许再次填写时须新建记录。

事务中的写入一起生效，失败则整体回滚，防止出现计数增加但答卷未保存等不一致。网络异常导致结果不明确时，应保留原幂等键和请求版本重试；已提交记录不能通过更换幂等键再次提交，也不能继续修改。

### 5.5 统计与反馈

统计先选出每个账号最后一次成功提交的整份答卷，再按版本和题目计算人数、选项及数字平均值。历史答卷保留，但最新答卷中的空值或跳题不能用旧答案补回。匿名结果对创建者隐藏账号身份，文本与数字答案支持分页查看。

新填写尚未提交或提交失败时，上一份成功答卷继续有效；筛选旧版本也不会重新计入已被新提交替换的答卷。各题分别统计经过人数和非空作答人数，多选题各选项人数之和可以超过作答人数。数字平均值只纳入有效数字，无有效答案时返回空值。


## 6. 运行条件

前端使用 HTML、CSS 和 JavaScript；后端采用 Flask、Waitress 与 PyMongo；数据库要求 MongoDB 7.0 及以上副本集，本地可以使用单节点副本集以支持事务。默认页面地址为 `http://127.0.0.1:5000`，配置通过 `.env` 指定。

数据库包含 `users`、`sessions`、`surveys`、`survey_versions`、`attempts`、`responses`、`participation_guards` 和 `submission_keys` 八个集合。题目、选项与规则嵌入问卷定义，持续增长的填写与答卷独立保存。
